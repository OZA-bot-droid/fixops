# FixOps v1.0 — 최종 결정 기록·불일치 검토

> **상태:** v1.0 설계 승인 후보 — 사용자 승인 정책 24개 및 권장 추가 쟁점 6개 반영. 실행·통합 테스트 전이며 코드 반영을 의미하지 않음.  
> **기준:** 2026-11-18 / 최종 발표 2026-12-21 / 5명·20영업일 / `OZA-bot-droid/fixops` main/docs v0.5~v0.5.4  
> **우선순위:** P0=시연 핵심 구현, P1=여력 시, P2=후속 확장.

## 1. 최종 판단

**설계 확정은 가능하나 구현 검증 완료를 의미하지 않는다.** 가입 정책 24개와 추가 논의 6개 권장안을 채택하며, 본 문서의 교차 서비스 경계·보안·정합성 보강 사항을 필수 계약으로 편입한다. 신규 대형 기능의 확대는 하지 않는다.

## 3. 추가 쟁점 6개 — 권장안 수용

1. **Organization / Complex 분리:** 단지는 물리 실체, 조직은 운영 주체. 활성 관리관계 최대 1개; 이력별 시작·종료 시간 기록. 복수 단지 소속 접근 제어 별도.
2. **동일 세대 복수 구성원:** 1:N 승인, 퇴거 시 세대 접근권한 즉시 정지, 추가 가족은 자동 우회 승인하지 않음.
3. **WorkOrder / Schedule:** 1:N 방문 이력, 단일 활성 확정 예약; 예약 취소·재예약 가능, 자동 반복은 P1.
4. **부품 사용:** Inventory가 실제 사용을 확정하고 재고 차감, 이후 정정은 보상 원장. 재고 부족은 오류·작업 상태와 별도 판단.
5. **AI 범위:** 조회·RAG·예약 후보 추천만. 사용자 확인 없이 업무 상태 변경 금지.
6. **Mock 경계:** 시연 데이터/외부 OTP 및 K-apt 대체만 Mock; JWT·권한·예약 충돌·재고 트랜잭션은 실제 구현.

## 5. 발견된 문서 불일치 / 해결

|---|---|
| v0.5 Spring Boot 3.4.x vs v0.5.1 Boot 4.0.9 | Boot 4.0.9 + Cloud 2025.1.3 **기술 검증 후보**. 빌드 통과 전 고정 완료 주장 금지 |

| RAG 문서 삭제/이전 권한 | 회원 조직·단지 스코프에 맞춘 문서 가시성 및 재색인·파기 |

## 6. 권한·데이터 관련 추가 위험 두 가지

- **다중 단지 관리에서 주민 데이터 누출:** `org_id`만 필터하는 쿼리는 실패로 취급한다. 반드시 `complex_id` 또는 승인된 `location_id` 기준으로 교차 검증.
- **관리권 이전 시 서비스 간 데이터 소유권:** Asset/WorkOrder/Inventory는 단지에 귀속된 이력을 유지하고, 운영 주체가 바뀌면 새 관리 주체의 접근권한을 조정한다. 과거 기록의 `organization_id`를 무작정 일괄 치환하지 않는다.

## 7. 미해결 전제 — 기술 검증이지 미승인 요구사항이 아님

- Spring Boot 4.0.9·Cloud 2025.1.3와 gRPC/OTel 실제 조합 빌드.
- Python LangChain 1.x와 MCP SDK 버전·Tool 연동.
- AWS 서울 리전 RDS 선택 마이너의 `vector` **0.8.2 지원 확인**.
- K-apt 응답 실제 필드/사용 조건과 데모 mock fallback.
- 도메인 호스트명, RDS/EC2 배포 리소스 ID, LLM 공급자와 예산 세부는 배포 설정 값으로 관리.

## 8. 결론 및 적용 규칙

본 결정 기록과 아래 7개의 계약서를 v1.0 기준 세트로 한다. 기존 v0.x 문서는 의사결정 이력이며 충돌하면 승인된 본 v1.0 계약을 우선한다. 운영 서비스 수준의 개인정보 적법성 검토·고가용성 인증을 완료한 것으로 해석하지 않는다.
