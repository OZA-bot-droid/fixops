# FixOps v1.0 — 문서 세트 안내

> 상태: 기존 v1.0 업무 설계 유지. 2026-11-25 인증 안정화 및 주민 등록 정책 개정은 `fixopsdev/fix/member-doc-alignment` 구현 기준이며 팀 승인·통합 테스트가 필요하다.
> 최종 발표 2026-12-21 / 5명·20영업일. P0=시연 핵심, P1=안정화, P2=후속 확장.

## 사용 방법

1. `00_` 결정·검토를 먼저 확인한다.
2. `01_` 통합 설계에서 컴포넌트와 범위를 확정한다.
3. `02_` ERD → `03_` 인가 → `04_` REST → `05_` AI/MCP → `06_` 트랜잭션 순으로 세부 계약을 리뷰한다.
4. `07_` AWS 및 `08_` WBS 검수 후 Jira·구현에 반영한다.
5. 인증/Redis 변경은 `09_`, `10_`의 최신 상태·검증 항목과 함께 확인한다.
6. 이메일 SMTP·주민 등록 코드 정책은 00/01/03, V9 스키마는 02, API는 04 v1.1, 배포·검증은 07, 화면은 08을 적용한다.

## 범위 및 주의

- GitHub `fixops`의 main/docs v0.5~v0.5.4 참고. 기존 조직·단지·권한 정책 유지. 인증 전달/오류/세션 정책은 04/09/10 참조.
- `contracts/error-codes.md`는 공식 오류 계약으로 사용하지 않는다.
- 2026-11-25 개정은 작업 브랜치에 반영되었으며 main 병합 및 팀 승인은 별도이다. 실제 Gmail 발송, V9 마이그레이션, 동시성, 브라우저 및 Redis 권한 회수 검증은 07의 T21~T29 및 09/10 기준으로 수행한다.
- 구현 커밋이 존재한다는 사실은 CI·통합 테스트 통과를 의미하지 않는다.
- RDS 확장·MCP SDK·Spring Boot 기술 조합은 실제 실행 검증 필요.
